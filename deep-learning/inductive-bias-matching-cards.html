Inductive bias matching

For each data type, decide which assumptions about its structure a model could exploit, then which architecture builds those assumptions in.

Be ready to say what each assumption would cost if it turned out to be false. That, rather than the match itself, is what we will discuss.

  • Type the code, not the name — A1, R4
  • An assumption card can be used on more than one data type
  • One architecture card per data type
  • Click a code to copy it

Assumption

A structural claim about the data. Eight cards, and one of them is a trap.

Locality

Elements that are close together are related. Distant ones usually are not — at least not directly.

Same pattern anywhere

A pattern means the same thing wherever it occurs, so the detector for it can be reused at every position.

Order matters

The elements come in an order, and reordering them changes the right answer.

Order does not matter

The input is a set. Reordering the elements must not change the answer at all.

Anything can depend on anything

Any element may depend on any other, however far apart, and which pairs matter changes from input to input.

It is a graph

What matters is which elements are connected to which — not the numbers we happened to give them.

Parts make wholes

Small pieces combine into larger pieces, which combine again. Meaning is built up in layers.

Every feature is its own thing

No two inputs are interchangeable; each one has its own separate meaning. There is no position, order, or neighbourhood to exploit.

Architecture

The model that builds those assumptions in. One of these is not a neural network.

MLP

Fully connected layers. Every input connects to every unit, with its own weight.

CNN

A small kernel slid over every position, its weights shared across positions. Stacked, with pooling.

RNN / LSTM

Reads one element at a time, carrying a fixed-size memory from step to step.

Transformer

Every element attends to every other in one step, with weights computed from the content.

GNN

Each node repeatedly collects messages from its neighbours and updates itself.

Gradient-boosted trees

Not a neural network. A committee of decision trees, each splitting on one column at a time.
