White-box Honesty Probes

I’m doing a BlueDot Technical AI Safety Project. This is the first step on my journey for producing technical AI safety research output. My main goals are to learn, learn, learn, produce something public-facing, and develop a process for advising my own students.

Project summary

Use activation probes (starting with linear) to detect deceptive/dishonest behaviour or output. Building on a paper that does this for detecting hallucinations.

The goal is to have a real-time, streaming classifier for which tokens/phrases contain deceptive/dishonest output.

I need to be very detailed about what deceptive/dishonest behaviours I’m testing for, for example, sycophancy (changing your mind when the user disagrees), sycophancy (reinforcing the user’s beliefs, even if false/delusional), lying (factual statement different from what you believe), reward hacking (giving an answer that seems correct (passes a test) but is not (does not solve the general problem), omission (stating only true facts but leaving important/relevant ones out), …

The hard part of this project is finding or creating data sets for these very specific behaviours. I’ll start by focussing on behaviours for which I can auto-generate data sets. Possibly using frontier LLMs to do data annotation. No manual labelling, except perhaps for spot-checking <100 automatically labelled samples.

Resources

  • The paper I’m replicating: Obeso, et al. (2025). Real-Time Detection of Hallucinated Entities in Long-Form Generation. Their repo on GitHub.

Assumptions and derisking

Main assumption: I can adapt Obeso’s method as-is to other kinds of dishonesty. This means generating and labelling ~10–20k data at the entity level. (Entity is fairly broadly defined, so this might be flexible for anything from word-level to sentence-level honesty labels.) It means running the existing pipeline on the new data set and recording performance metrics. I can combine various linear probles into a multi-variate probe that produces dishonesty vector scores at inference time. This is the project, revisit to break it down further.

Other assumptions:

  • It is straightforward to use and adapt Obeso, et al’s data generation and labelling pipeline. I see one issue about this on their GitHub repo, from December 2025, so not sure if there is a problem there.
    • Why it matters: I need to generate my own data using their process.
    • Importance: High. No data, no project.
    • P(success): 9/10.
    • Time: 1d
    • Priority: 1. Crucial to my project running; need to derisk.
  • Obeso’s method seems to work but, to the best of my knowledge, Obeso, et al has not been reused or replicated by others. Need to see if anyone cites them. Need to search if anyone uses their method.
    • Why it matters: If others cite them, it helps validate the method’s usefulness. If others don’t cite them, I don’t learn anything since it might just be too new or obscure. It might also be that I find others doing what I want to do, which would change my research direction.
    • Importance: Medium. My main goal is learning and not novelty, so okay if it’s obscure or if others are doing it too. It would be better if I do something novel though.
    • P(success): 9/10. I’ll learn something either way.
    • Time: ¼d. Find citing papers. Quick check for what thoes papers do.
    • Priority: 1. Might affect my research direction. Small time commitment.
  • If all this works, who would care? I’ll eventually target my write-up at these people. This project requires white-box access, so anyone working with model internals. Unfortunately, I think the testing orgs (e.g. UKAISI) have black-box access only, so perhaps not useful to them. The AI labs would care since it can be used as an extra signal during model evals. Need to think about how to market this to them. Anyone working with open source models, commercially or for research, would find an inexpensive multi-variate dishonesty probe useful. For commercial use, assuming it is inexpensive to run, it could even be used to monitor model outputs in real time and flag potentially dishonest outputs so those can be checked and the model or prompt tweaked to reduce risk. To do: Validate who would care by talking to people, reading who uses white-box methods and how.
    • Importance: Medium. I can still learn and write without doing an audience analysis. This would make my write-up more impactful though.
    • P(success): 2/3. Not sure I’ll be able to find the information I need.
    • Time: 1d. Cumulative time needed to find and contact people and find and read articles.
    • Priority: 2.
  • Compute needs seem mild. I was able to reproduce one small model’s results on the full data set with 2.5h and ~$2 of compute. I’m not sure what this looks like for a 70B model, which is the largest they used. It seems this should scale though. In the worst case, I need a grant to run a larger model on a larger GPU. Can test by running 70B on a small dataset.
    • Why it matters: Compute cost for larger models might be prohibitive, although I think it won’t be. I can still run experiments on smaller models, say 1B–8B and learn something useful.
    • Importance: Medium.
    • P(success): 9/10. To discove the compute requirements for 70B.
    • Time: ¼d. Will also need some $ to load the 70B model on a high RAM GPU and run the first part of the existing data set.
    • Priority: 2. Small time commitment, but does not affect project direction, just whether or not I run a large model.
  • I have to generate my own dishonesty data. Obeso’s data is available on HuggingFace. I can easily reuse their data for hallucination detection. However, I’ll need new data for other kinds of dishonesty. I can perhaps find data for some of it, but long-form data?
    • Why it matters: It’s quicker to reuse existing data, as long as it’s reliable. Even if it’s not reliable, it could still feed into the better data ⇒ better accuracy hypothesis in the next point.
    • Importance: Medium.
    • P(success): 1/4. Not sure if there is suitable data.
    • Time: ½d. Search for data, check for suitability, and spot-check label quality.
    • Priority: 3. Low confidence that I’ll want to use external data anyway since it needs to be entity-labelled, but I could learn from other papers how they prompt models into dishonesty.
  • I can improve on their results if I cleaned up their data. Their label reliability seems okay but not great. The goal here needs to be speed (of data generation) and accuracy. They went for speed, but at the expense of some labels being inaccurate. Find an automated way to verify the facts they extracted (in entities) using another frontier LLM perhaps and/or another prompt. This would still be very fast, but more expensive, and presumably yield better accuracy.
    • Why it matters: Better data ⇒ better accuracy, but will I use their data? This could be a mini-project on its own: I already have their inference code running on their data. Now, improve their data and run again. Better metrics would validate my data quality hypothesis (better data ⇒ better accuracy).
    • Importance: Medium. I want to do honesty more broadly. However, this is a nice tiny, self-contained project.
    • P(success): 2/3. Getting it working. I’d estimate P = 1/4 for validating my hypothesis.
    • Time: 1d. High uncertainty here since I’ve not worked with their data pipeline yet.
    • Priority: 3. A nice small side-project but not on the critical path for mine. However, if it works, I’ll want to run my own data pipeline the same way. but, I can do that after running v1 of my pipeline, based on the Obeso pipeline.

  • Advising meeting with Jazon. Notes:
    • Write things up consistently and focus on comms.
    • MVP
      • Divide the project into an atomic contribution, a minimum value add that you’re still happy with.
      • It could be upskilling goals rather than research output. What is the core contribution you can do regardless of everything going wrong? People tend to be too optimistic.
      • A lot of AI safety research is done in sprints, since the field assumes timelines are short. If you’re too ambitious, you can waste your time. (This is different from academia.) An MVP helps you figure out if it can be done (derisking), otherwise move on.
      • Reasonable MVP output: a good GitHub repo; perhaps a LessWrong post.
    • Theory of change
      • One of the primary things you have to communicate is how what you’re doing is reducing the risk of bad outcomes / increasing the chances of good outcomes. So, make your theory of change explicit.
      • This is part of AI safety research culture.
      • This can also affect design choices. Prioritize research directions that are closely related to the “route to value” according to your theory of change. Always be ready to answer, “What is the point of this work?”
    • Ideas on my project
      • Detecting “role-play” dishonesty would be a good addition.
      • Intervention would be good too: steering with linear activation vector.
      • Think of what you definitely want to accomplish and then extensions.
      • Be able to answer what evidence would suggest that you should change research direction. How do you keep yourself honest about being on a productive research track?
      • Larger models might encode things differently. So, look at those too; compare, say, ~1B to ~10B to ~100B.
    • Coming up with a baseline for dishonesty
      • Look at chain of thought - does the model say it’s lying? This requires a reasoning model, which I’m not using right now. Reasoning models push up the number of output tokens a lot, making them more expensive.
      • I need to look at the dishonesty literature to find a good baseline for dishonesty detection.
    • Next time: Make design decisions about the exact type of dishonesty I’m doing, a data set for it, and baselines to compare against.
