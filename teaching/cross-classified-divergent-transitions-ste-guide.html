Cross-Classified Models and Divergent Transitions: A Guide in Simplified Technical English

It gives all the concepts, skills and examples from Section 13.3 and Section 13.4 of Statistical Rethinking, second edition, by Richard McElreath. It is not a summary. Each idea from these sections is in this paper.

2. More than one type of cluster

Main point: One observation can belong to more than one cluster. Then a model can have varying intercepts for each type of cluster, with partial pooling on each type at the same time.

2.1 Actors and blocks

We can use more than one type of cluster in the same model, and frequently we should. For example, think about the chimpanzee data we modeled in a previous class using binomial regression (Section 11.1 in the textbook). The observations are lever pulls.

  • Each pull is in a cluster of pulls from one chimpanzee (the actor).

  • Each pull is also in an experimental block. A block is a group of observations from the same day.

Thus, each pull belongs to an actor (1 to 7) and to a block (1 to 6). Each actor can have its own intercept, and each block can also have its own intercept.

In this paper, we use the two types of cluster in the chimpanzee data at the same time. Thus, we can use partial pooling on the two categorical variables, actor and block, at the same time. We also get estimates of the variation among the actors and of the variation among the blocks.

2.2 Cross-classification and hierarchy

The structure of the chimpanzee data is usually called a cross-classifiedᴳ multilevel model. It is cross-classified because the actors are not nested in unique blocks. Each chimpanzee pulled levers in all the blocks.

Suppose that each chimpanzee did all its pulls on one day, in one block. Then the data structure is hierarchicalᴳ (nested). But usually the model is the same. Thus, the model structure and the code in this paper apply to cross-classified designs and to hierarchical designs. Some other software makes you use different models for the two designs, because its estimation method is much less capable than MCMC.

There are other types of "hierarchical" multilevel models, which put adaptive priors on adaptive priors. You will see an example in the next class session. But in most cases, people (and their software) use the same type of model for the two designs.

3. Multilevel chimpanzees

Main point: To add a second type of cluster, copy the structure of the first type: a new varying intercept, a new adaptive prior and a new standard deviation. The chimpanzees vary very much, but the blocks are almost the same.

3.1 The model

Start with the chimpanzee model m11.4 from the paper about binomial regression (Section 11.1 in the textbook). Then add varying intercepts:

  1. Replace the fixed regularizing prior on the actor intercepts with an adaptive prior.

  2. Add the second type of cluster, block. To do this, copy the structure of the actor cluster. The linear model gets one more varying intercept, γ_BLOCK[i]. The model also gets one more adaptive prior and one more standard deviation parameter.

The model is:

Li∼Binomial(1,pi)logit(pi)=αACTOR[i]+γBLOCK[i]+βTREATMENT[i]βj∼Normal(0,0.5)for j=1,…,4αj∼Normal(αˉ,σα)for j=1,…,7γj∼Normal(0,σγ)for j=1,…,6αˉ∼Normal(0,1.5)σα∼Exponential(1)σγ∼Exponential(1)\begin{aligned} L_i &\sim \text{Binomial}(1, p_i) \\ \text{logit}(p_i) &= \alpha_{\text{ACTOR}[i]} + \gamma_{\text{BLOCK}[i]} + \beta_{\text{TREATMENT}[i]} \\ \beta_j &\sim \text{Normal}(0, 0.5) && \text{for } j = 1, \dots, 4 \\ \alpha_j &\sim \text{Normal}(\bar{\alpha}, \sigma_\alpha) && \text{for } j = 1, \dots, 7 \\ \gamma_j &\sim \text{Normal}(0, \sigma_\gamma) && \text{for } j = 1, \dots, 6 \\ \bar{\alpha} &\sim \text{Normal}(0, 1.5) \\ \sigma_\alpha &\sim \text{Exponential}(1) \\ \sigma_\gamma &\sim \text{Exponential}(1) \end{aligned}

The new parts are the γ terms, the adaptive priors, and the two standard deviations.

Each type of cluster has its own vector of parameters:

  • For the actors, the vector is α. It has length 7, because there are 7 chimpanzees in the sample.

  • For the blocks, the vector is γ. It has length 6, because there are 6 blocks.

Each cluster variable needs its own standard deviation parameter. This parameter adapts the quantity of pooling across the units (actors or blocks). These parameters are σ_α and σ_γ.

There is only one global mean parameter, ᾱ. We cannot identify a separate mean for each type of varying intercept, because the two intercepts are added in the same linear prediction. If you include a mean for each type of cluster, this does not cause a disaster. But the two means are not identifiable separately.

3.2 Fit the model

Load the data and make the index variables. The treatment index combines prosoc_left and condition, as in binomial regression:

d = pd.read_csv(DATA + "chimpanzees.csv", sep=";")
actor = d["actor"].values - 1                                   # 0 to 6

There are 504 pulls, 7 actors and 6 blocks. Now fit the model that uses actor and block:

with pm.Model(coords=coords) as m13_4:
    b = pm.Normal("b", 0, 0.5, dims="treatment")
    # hyperpriors
    a_bar = pm.Normal("a_bar", 0, 1.5)
    sigma_a = pm.Exponential("sigma_a", 1)
    sigma_g = pm.Exponential("sigma_g", 1)
    # adaptive priors
    a = pm.Normal("a", a_bar, sigma_a, dims="actor")
    g = pm.Normal("g", 0, sigma_g, dims="block")
    p = pm.math.invlogit(a[actor] + g[block_id] + b[treatment])
    pm.Bernoulli("L", p=p, observed=L)
    idata_13_4 = pm.sample(1000, chains=4, random_seed=13,
                           idata_kwargs={"log_likelihood": True})

print("divergent transitions:", int(idata_13_4.sample_stats["diverging"].sum()))
divergent transitions: 45

A binomial distribution with one trial is a Bernoulli distribution, so the code uses pm.Bernoulli.

You get 4000 samples from 4 independent chains. Always examine the trace plots and the diagnostics. When you start to trust the machine, the machine will betray your trust. Here, PyMC gives a warning about divergent transitionsᴳ. The textbook reports 22 divergent transitions. PyMC uses a lower default target acceptance rateᴳ than the textbook (0.8, not 0.95), so it often reports more.

The model actually sampled correctly. But the warnings tell us that the sampler had some problems when it explored the posterior efficiently. Section 8 shows how to fix this. For now, interpret the posterior.

There are two important features:

  1. The effective sample sizeᴳ (ESS) changes very much across the parameters. This is common in complex models. There are many possible reasons. In this type of model, a common reason is that a parameter spends much time near a boundary. Here, this parameter is sigma_g. It spends much time near its minimum of zero. Some R-hatᴳ values are also a little above 1.00. All of this shows that the sampling is not efficient. Section 8 fixes this.

  2. The estimated variation among the actors (sigma_a) is much larger than the estimated variation among the blocks (sigma_g). The right plot in Figure 1 shows this clearly. There is uncertainty about the variation among the actors. But the model is confident that the actors vary more than the blocks. You can also see this in the varying intercepts: the a distributions are much more spread out than the g distributions. The chimpanzees are different, but the blocks are all the same.

4. Compare with the actor-only model

Main point: The block intercepts shrink almost to zero, so they add little flexibility and little risk of overfitting. Do not select one model. Keep and report the two models, because together they tell more about the experiment.

4.1 The model without blocks

The block intercepts did not add much risk of overfitting. To see this, compare the model with only actor intercepts to the model with actor and block intercepts. The model that ignores block is:

4.2 Compare with WAIC

ArviZ 1.x does not have a WAIC function, so calculate WAIC directly from the pointwise log-likelihoods, as in the previous paper:

def waic(idata, var="L"):
    """WAIC on the deviance scale, and the effective number of parameters."""
    ll = idata.log_likelihood[var].values
    ll = ll.reshape(-1, ll.shape[-1])                 # samples x observations
    lppd = np.sum(np.log(np.mean(np.exp(ll), axis=0)))
    p_waic = np.sum(np.var(ll, axis=0))
    return -2 * (lppd - p_waic), p_waic

Look at the pWAIC column. It gives the effective number of parameters. The model m13_4 has 7 more parameters than m13_5, but it has only approximately 2 more effective parameters. Why?

  • The posterior distribution of sigma_g is near zero. Thus, the 6 g parameters all shrink strongly towards zero. They are not very flexible.

  • The a parameters shrink much less towards their mean, because the estimated variation across the actors is much larger. Thus, each a parameter adds much more to pWAIC.

The difference in WAIC between the two models is small: only approximately 1. This difference is very small compared to the standard error of the difference (1.71 in the textbook). The two models make almost the same predictions, so their expected out-of-sample accuracy is almost the same. The block parameters shrink so much towards zero that they do very little in the model.

4.3 Do not select a model

You possibly want to "select" one model as the best model. Stop and think. There is nothing to gain when you select one of these two models. The comparison tells a better story: it is not important if we include block or not, and the g and sigma_g estimates tell us why. When we keep and report the two models, we and our readers learn more about the experiment.

Model comparison is useful. But if you want to select a model, it is better to test the conditional independencies of different causal models. This is an experiment, so there is nothing to select. The experimental design tells us which causal model to examine.

5. Even more clusters

Main point: You can also use partial pooling on the treatment effects. Use varying effects when the units are exchangeable, not only when a variable was not controlled in the experiment.

5.1 Partial pooling on treatments

The treatment effects (the b parameters) look very similar to the a and g parameters. Can we also use partial pooling on the treatment effects? Yes, we can.

Some people will say "No!", because they learned that varying effects are only for variables that the experiment did not control. They think that the experiment "fixed" the treatment, so we must use "fixed" effects without pooling.

This is not correct. We use varying effects because they give better inferences. It is not important how the clusters occur. If the individual units are exchangeableᴳ, then partial pooling can help. Exchangeable means that you can change the index values of the units, and the meaning of the model does not change.

Here, there are only four treatments, and there is much data for each treatment. Thus, partial pooling will not make much difference. Here is m13_4 with partial pooling on the treatments:

6. Divergent transitions

Main point: A divergent transition occurs when the energy at the end of an HMC transition is not the same as the energy at the start. This occurs where the posterior is very steep. Fix it with a higher target acceptance rate, or with a reparameterization.

6.1 What a divergent transition is

The models in Sections 3 to 5 gave warnings about divergent transitions. Chapter 9 in the textbook first mentions them. Now we learn what they are and some useful ways to fix them. Divergent transitions are very common in multilevel models. Thus, you must know how to fix them, and for this you must know what causes them.

Hamiltonian Monte Carloᴳ (HMC) has internal checks of efficiency and accuracy. We will learn a lot more about HMC and its internal checks from next week. One of these checks comes from the physics of the simulation:

  1. HMC simulates the movement of a particle on a surface with no friction.

  2. In each transition (one "flick" of the particle), the total energy at the start must be equal to the total energy at the end. This is how energy works in a closed system.

  3. In an exact mathematical system, the energy is always conserved.

But in a numerical system, the energy is possibly not conserved. Sometimes the total energy at the end is not the same as at the start. Then the energy is divergent. This usually occurs when the posterior distribution is very steep in some region of the parameter space. A simulation with discrete steps cannot easily follow steep changes in probability. The algorithm compares the energy at the start with the energy at the end. When they are different, this shows numerical problems in that part of the posterior distribution.

The sampler rejects divergent transitions. They do not directly damage your approximation of the posterior distribution. But they damage it indirectly, because it is difficult to explore the region where they occur correctly. Even when there are no divergent transitions, distributions with steep regions are difficult to explore, and the chains are less efficient. This occurs frequently in multilevel models.

6.2 Two fixes

There are two easy methods to decrease the effect of divergent transitions:

  1. Tune the simulation so that it does not go past the wall of the valley. To do this, use more warmupᴳ and a higher target acceptance rate. In PyMC, this is target_accept. But for many models, you cannot tune the sampler enough to remove all the divergent transitions.

  2. Write the statistical model in a different form. This is reparameterizationᴳ. You can write each statistical model in different forms that are mathematically the same but numerically different.

Sections 7 and 8 give two examples.

7. The Devil's Funnel

Main point: When the scale of one parameter depends on another parameter, the posterior can have the shape of a funnel. HMC cannot sample the neck of the funnel. A non-centered parameterization samples a standardized variable and then calculates the original variable from it.

7.1 A simple funnel

You do not need a complex model to get divergent transitions. Look at this joint distribution of two variables, v and x:

v∼Normal(0,3)x∼Normal(0,exp⁡(v))\begin{aligned} v &\sim \text{Normal}(0, 3) \\ x &\sim \text{Normal}(0, \exp(v)) \end{aligned}

There are no data here. There is only a joint distribution to sample from. This distribution is a typical multilevel distribution, in which the scale of one variable (x) depends on another variable (v). Sample from it with PyMC:

with pm.Model() as m13_7:
    v = pm.Normal("v", 0, 3)
    x = pm.Normal("x", 0, pm.math.exp(v))
    idata_13_7 = pm.sample(1000, chains=4, random_seed=7)

print("divergent transitions:", int(idata_13_7.sample_stats["diverging"].sum()))
az.summary(idata_13_7, ci_prob=0.89).round(2)
divergent transitions: 504
Parametermeansd5.5%94.5%ESSR-hat
v2.001.90-1.005.30171.17
x-2.0076.40-71.0047.003451.13

The problem looks easy, because there are only two parameters. But the result is a disaster. There are many divergent transitions, and the ESS and R-hat values are very bad. The true mean of v is 0 and the true standard deviation is 3, but the estimates are far from these values. Also look at the trace plot, with az.plot_trace(idata_13_7).

This example is The Devil's Funnelᴳ. When v is low, the distribution of x contracts around zero. This makes a very steep valley that the Hamiltonian particle must explore. Steep surfaces are difficult to simulate, because the simulation is not continuous. It uses discrete steps. If the steps are too large, the simulation goes past the correct path. This error changes the total energy in the system. After this, the result cannot be predicted.

A divergent transition is a proposal for which the energy at the start of the transition is not the same as the energy at the end. With this distribution, you get many divergent transitions and an approximation of the posterior distribution that is not reliable. We know this because the distribution is very simple: we can calculate it exactly.

7.2 Centered and non-centered

We can fix this problem with a reparameterization. There are two general ways to parameterize a model in which the distribution of one parameter is a function of another parameter.

In the funnel, the distribution of x is a function of v:

x∼Normal(0,exp⁡(v))x \sim \text{Normal}(0, \exp(v))

This is the cause of the funnel. When v changes, the distribution of x changes in a very inconvenient way. This form is the centered parameterizationᴳ. The name is not very intuitive. It only means that the distribution of x is conditional on one or more other parameters.

The alternative is a non-centered parameterizationᴳ. It moves the embedded parameter (here v) out of the definition of the other parameter:

v∼Normal(0,3)z∼Normal(0,1)x=zexp⁡(v)\begin{aligned} v &\sim \text{Normal}(0, 3) \\ z &\sim \text{Normal}(0, 1) \\ x &= z \exp(v) \end{aligned}

This looks strange. To understand it, think about how we standardize a variable:

  1. Subtract the mean.

  2. Divide by the standard deviation.

The new standardized variable has mean zero and standard deviation one. To get the original variable again, do these steps in the opposite sequence:

  1. Multiply the standardized variable by the original standard deviation.

  2. Add the original mean.

The reparameterization above defines z as the standardized x. Thus, z has mean zero and standard deviation one. To calculate x, we reverse the standardization: we multiply z by the standard deviation exp(v). There is no mean to add, because here the mean is zero. If there is a different mean, add it in this step. The result is that x in the non-centered version has the same distribution as x in the centered version. It is the same joint distribution of v and x.

But the Markov chain is very different. We do not sample x directly. We sample z. Sample the non-centered model:

with pm.Model() as m13_7nc:
    v = pm.Normal("v", 0, 3)
    z = pm.Normal("z", 0, 1)
    x = pm.Deterministic("x", z * pm.math.exp(v))
    idata_13_7nc = pm.sample(1000, chains=4, random_seed=7)

print("divergent transitions:", int(idata_13_7nc.sample_stats["diverging"].sum()))
az.summary(idata_13_7nc, ci_prob=0.89).round(2)

We sampled the funnel correctly because we sampled a different variable and then transformed it. This is the non-centered parameterization. It is frequently used in multilevel models. But sometimes the centered prior is better. Thus, you must be able to use the two forms.

8. Non-centered chimpanzees

Main point: A higher target acceptance rate can remove divergent transitions, but the chains can still be inefficient. A non-centered version of the model moves the hyperparameters out of the adaptive priors and into the linear model. It samples much more efficiently.

8.1 First, try a higher target acceptance rate

Now use the method on the chimpanzees. In m13_4, the adaptive priors have parameters inside them. These parameters cause regions of steep curvature, and these regions cause divergent transitions.

Before you reparameterize, try a higher target acceptance rate. In PyMC, the target_accept option controls it. The PyMC default is 0.8, so the sampler tries to get an 80% acceptance rate. It does this during the warmup (tuning) phase, when it adjusts the step size of each leapfrog stepᴳ (Chapter 9 in the textbook explains these terms). A high target_accept gives a smaller step size. Thus, the approximation of the curved surface is more accurate. But the exploration of the distribution can also be slower.

A higher target_accept often helps with divergent transitions, but not always. Sample m13_4 again with a higher target acceptance rate. The model m13_4 already exists, so use it again:

with m13_4:
    idata_13_4b = pm.sample(1000, chains=4, random_seed=13, target_accept=0.99)

print("divergent transitions:", int(idata_13_4b.sample_stats["diverging"].sum()))
divergent transitions: 0

This helped. (The textbook reports 2 divergent transitions with a target acceptance rate of 0.99.) But sometimes this is not sufficient. Also, the chain is still not very efficient. Look at az.summary(idata_13_4b): many of the ESS values are much smaller than the true number of samples (4000: 4 chains with 1000 samples each).

8.2 The non-centered model

The non-centered version of the model is much better. We want a version of m13_4 in which the parameters move out of the adaptive priors and into the linear model. There are two adaptive priors to transform:

αj∼Normal(αˉ,σα)[intercepts for actors]γj∼Normal(0,σγ)[intercepts for blocks]\begin{aligned} \alpha_j &\sim \text{Normal}(\bar{\alpha}, \sigma_\alpha) && \text{[intercepts for actors]} \\ \gamma_j &\sim \text{Normal}(0, \sigma_\gamma) && \text{[intercepts for blocks]} \end{aligned}

There are three embedded ("centered") parameters to move out of these priors: ᾱ, σα and σγ. As with the funnel, define new variables with standard Normal distributions. Then calculate the original variables again: reverse the transformation. This time, do this calculation in the linear model. The non-centered model is:

Li∼Binomial(1,pi)logit(pi)=αˉ+zACTOR[i]σα⏟αACTOR[i]+xBLOCK[i]σγ⏟γBLOCK[i]+βTREATMENT[i]\begin{aligned} L_i &\sim \text{Binomial}(1, p_i) \\ \text{logit}(p_i) &= \underbrace{\bar{\alpha} + z_{\text{ACTOR}[i]} \sigma_\alpha}_{\alpha_{\text{ACTOR}[i]}} + \underbrace{x_{\text{BLOCK}[i]} \sigma_\gamma}_{\gamma_{\text{BLOCK}[i]}} + \beta_{\text{TREATMENT}[i]} \end{aligned}

The priors are:

βj∼Normal(0,0.5)for j=1,…,4zj∼Normal(0,1)[standardized actor intercepts]xj∼Normal(0,1)[standardized block intercepts]αˉ∼Normal(0,1.5)σα∼Exponential(1)σγ∼Exponential(1)\begin{aligned} \beta_j &\sim \text{Normal}(0, 0.5) && \text{for } j = 1, \dots, 4 \\ z_j &\sim \text{Normal}(0, 1) && \text{[standardized actor intercepts]} \\ x_j &\sim \text{Normal}(0, 1) && \text{[standardized block intercepts]} \\ \bar{\alpha} &\sim \text{Normal}(0, 1.5) \\ \sigma_\alpha &\sim \text{Exponential}(1) \\ \sigma_\gamma &\sim \text{Exponential}(1) \end{aligned}

The vector z gives the standardized intercept for each actor. The vector x gives the standardized intercept for each block. In the linear model logit(p_i), all the parameters that were embedded in the priors occur again. Each actor intercept is:

αj=αˉ+zjσα\alpha_j = \bar{\alpha} + z_j \sigma_\alpha

Each block intercept is:

γj=xjσγ\gamma_j = x_j \sigma_\gamma

These expressions are now in the linear model. Sample from this posterior:

with pm.Model(coords=coords) as m13_4nc:
    b = pm.Normal("b", 0, 0.5, dims="treatment")
    a_bar = pm.Normal("a_bar", 0, 1.5)
    sigma_a = pm.Exponential("sigma_a", 1)
    sigma_g = pm.Exponential("sigma_g", 1)
    z = pm.Normal("z", 0, 1, dims="actor")             # standardized actor intercepts
    x = pm.Normal("x", 0, 1, dims="block")             # standardized block intercepts
    a = pm.Deterministic("a", a_bar + z * sigma_a, dims="actor")
    g = pm.Deterministic("g", x * sigma_g, dims="block")
    p = pm.math.invlogit(a[actor] + g[block_id] + b[treatment])
    pm.Bernoulli("L", p=p, observed=L)
    idata_13_4nc = pm.sample(1000, chains=4, random_seed=13)

print("divergent transitions:", int(idata_13_4nc.sample_stats["diverging"].sum()))
divergent transitions: 1

This model uses the default target_accept of 0.8, and it has almost no divergent transitions.

8.3 Compare the effective sample sizes

Now compare the effective sample sizes of the two forms. To compare them correctly, ignore the z and x parameters. Compare the a and g parameters. This is why the code uses pm.Deterministic for a and g: PyMC calculates them during sampling and keeps them in the posterior.

The code below gets the ESS values for the same parameters from the two models, and plots them against each other:

pars = ["a", "g", "b", "a_bar", "sigma_a", "sigma_g"]
ess_c = az.ess(idata_13_4, var_names=pars)
ess_nc = az.ess(idata_13_4nc, var_names=pars)
ess_c = np.concatenate([np.atleast_1d(ess_c[v].values) for v in pars])
ess_nc = np.concatenate([np.atleast_1d(ess_nc[v].values) for v in pars])

fig, ax = plt.subplots(figsize=(4.6, 4.2))
ax.plot(ess_c, ess_nc, "o", mfc="none", mec=DARK, ms=6, mew=1.5)
lim = [0, max(ess_c.max(), ess_nc.max()) * 1.05]
ax.plot(lim, lim, ls="--", color=DARK, lw=1)
ax.set_xlim(lim)
ax.set_ylim(lim)
ax.set_xlabel("ESS (centered)")
ax.set_ylabel("ESS (non-centered)")
plt.show()
print(np.sum(ess_nc > ess_c), "of", len(ess_c), "parameters sample better non-centered")
20 of 20 parameters sample better non-centered

Figure 3. A comparison of the centered (horizontal) and non-centered (vertical) parameterizations of the multilevel chimpanzee model m13_4. Each point is a parameter. The dashed diagonal shows where the two models give the same effective sample size. All the points are above the diagonal, so the non-centered parameterization samples better.

For all the parameters, the non-centered parameterization is much better. In the textbook, the result is the same for all but two parameters.

8.4 Centered or non-centered?

Must we always use the non-centered parameterization? No. Sometimes the centered form is better. The centered form can be better for one cluster in a model, while the non-centered form is better for a different cluster in the same model. It depends on the details:

  • A cluster with low variation, for example the blocks in m13_4, usually samples better with a non-centered prior.

  • A cluster with many units but not much data for each unit usually also samples better with a non-centered prior.

It is very useful to be able to change between the two forms when necessary.

8.5 Other distributions

You can also reparameterize distributions that are not Gaussian. For example, an exponential distribution has one scale parameter, usually called λ. You can move λ out of the distribution and into a linear model:

x=zλz∼Exponential(1)\begin{aligned} x &= z \lambda \\ z &\sim \text{Exponential}(1) \end{aligned}

Then x has an exponential distribution with scale λ (mean λ). The textbook writes this as x ~ Exponential(λ). Be careful: PyMC's pm.Exponential uses the rate lam = 1/λ. A quick check with simulation:

lam = 2.0
z = rng.exponential(1.0, 100_000)       # z ~ Exponential(1)
x = z * lam                             # x = z * lambda
print(x.mean(), stats.expon(scale=lam).mean())
1.990561219872559 2.0

The mean of x is approximately 2, the same as an exponential distribution with scale 2.

9. Glossary

The terms are in alphabetical order. The links in the text go to these entries.

Centered parameterization

A form of a model in which the distribution of one parameter has other parameters inside it, for example x ~ Normal(0, exp(v)) or αj ~ Normal(ᾱ, σα).

Cross-classified model

A multilevel model in which each observation belongs to clusters of two or more types, and the clusters of one type are not nested in the clusters of the other type.

Divergent transition

An HMC transition in which the total energy at the end is not the same as the total energy at the start. It shows that the posterior is too steep in that region for the sampler to follow.

Effective sample size

The number of independent samples that give the same information as the correlated samples from a Markov chain. Its short name is ESS.

Exchangeable

Units are exchangeable when you can change their index values and the meaning of the model does not change.

Hamiltonian Monte Carlo

An MCMC method that simulates a particle that moves with no friction on the surface of the negative log-posterior. Its short name is HMC.

Hierarchical

A data structure in which the clusters of one type are nested in the clusters of another type.

Leapfrog step

One small step of the HMC simulation of the movement of the particle.

Non-centered parameterization

A form of a model in which a standardized variable has a standard Normal distribution, and the original variable is calculated from it, for example x = z exp(v).

R-hat

A diagnostic that compares the variation within each chain to the variation between the chains. Values above 1.00 show that the chains possibly did not converge.

Reparameterization

To write a model in a different form that is mathematically the same but numerically different.

Target acceptance rate

The acceptance rate that the sampler tries to get during warmup. A higher value gives smaller steps. In PyMC, it is target_accept.

The Devil's Funnel

A joint distribution in which the scale of one variable depends on another variable, so that the posterior has the shape of a funnel with a very steep neck.

Warmup

The first part of each Markov chain, in which the sampler adjusts its step size. PyMC calls it tuning. The warmup samples are not used.
