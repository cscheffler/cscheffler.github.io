2. Models with memory

Main point: Many models forget what they learn about one cluster when they estimate the next cluster. A multilevel model learns about each cluster and about the population of all clusters at the same time. Thus, it can transfer information between clusters.

2.1 Models with amnesia

Some people have anterograde amnesia. They cannot make new long-term memories. Each moment is new for them. For example, each cup of coffee is the first cup of coffee that they remember.

Many statistical models also have this type of amnesia. The data are often in clustersᴳ, for example individuals, groups or locations. A model estimates parameters for each cluster. When the model goes from one cluster to the next cluster, it forgets all that it learned about the previous clusters.

The models in the previous papers that used an index variable (or a dummy variableᴳ) for categories have this amnesia. These models assume that the data from one category give no information about the other categories. The parameters are independent. Each parameter learns from a different part of the data. This is like when you go to a new café and you forget that you were ever in a café before. Cafés are different, but they are also similar.

Amnesia is bad for learning about the world. We want models that use all of the information well. This does not mean that we treat all the clusters as the same. It means that we learn about each cluster and about the population of clusters at the same time. When we do the two tasks at the same time, we can transfer information between the clusters. This transfer makes the estimates more accurate. This is the value of memory.

2.2 The coffee robot

Think about cafés again. We program a robot to go to two cafés, order coffee and estimate the waiting time at each café.

  1. The robot starts with a vague prior for the waiting times. For example, the prior has a mean of 5 minutes and a standard deviation of 1 minute.

  2. At the first café, the robot orders a cup of coffee. It observes a waiting time of 4 minutes.

  3. The robot uses Bayes' theorem to update its prior with this observation. The result is a posterior distribution for the waiting time at the first café.

Now the robot goes to the second café. What is its prior at the second café?

  • The robot can use the posterior from the first café as its prior for the second café. But this assumes that the two cafés have the same average waiting time. Cafés are similar, but they are not identical.

  • The robot can ignore the observation from the first café. But this is amnesia, and it is not sensible either.

How can the robot do better? It must represent the population of cafés and learn about this population. The distribution of waiting times in the population becomes the prior for each café. But this prior is different from the priors in the previous papers: the robot learns this prior from the data.

Thus, the robot tracks one parameter for each café. It also tracks at least two parameters for the population of cafés: an average and a standard deviation. Each time the robot observes a waiting time, it updates all the estimates. It updates the estimate for each café and the estimates for the population:

  • If the population has much variation, then the prior is flat and gives little information. Thus, an observation at one café changes the estimate for another café very little.

  • If the population has little variation, then the prior is narrow and gives much information. Thus, an observation at one café changes the estimates for the other cafés very much.

This argument leads to multilevel modelsᴳ. These models remember the features of each cluster while they learn about all the clusters. The model also learns the variation among the clusters from the data. This variation controls how much the model poolsᴳ information across the clusters. Pooling usually makes the estimate for each cluster better.

3. Benefits and costs of multilevel models

Main point: Multilevel models give better estimates in many types of data. They should be the default approach to regression. But they need new assumptions, MCMC, and more care when you interpret them.

3.1 Four benefits

Better estimates for each cluster give four practical benefits. Chapter 1 in the textbook also gives them:

  1. Better estimates for repeated sampling. Sometimes more than one observation comes from the same individual, location or time. Then traditional single-level models either underfit or overfit the data as much as possible.

  2. Better estimates when the sampling is not balanced. Sometimes we sample some individuals, locations or times more than others. Multilevel models automatically include the different uncertainty of these clusters. This prevents the clusters with many samples from having too much influence on the inference.

  3. Estimates of variation. Sometimes our research questions are about the variation among individuals or other groups in the data. Then multilevel models are very useful, because they model the variation explicitly.

  4. No averaging, so the variation stays. Researchers frequently average some data before they make variables. This can be dangerous. Averaging removes variation. Also, there are usually different ways to calculate the average. Thus, averaging gives false confidence, and it adds data transformations that are arbitrary. Multilevel models keep the uncertainty, and you do not need these data transformations.

All of these benefits come from the same strategy and the same model structure. You learn one basic design, and you get all four benefits.

For regression, multilevel regression should be the default approach. In some situations, an old-fashioned single-level model is better. But there are many more situations in which a multilevel model is better. It is better to start with a multilevel analysis and then find that you do not need it, than to forget it. When you know the basic multilevel strategy, it is also easier to add related methods, for example models for measurement error and for missing data.

3.2 Three costs

The multilevel approach also has costs:

  1. New assumptions. We must define the distributions from which the features of the clusters come. Conservative maximum entropy distributions do this very well.

  2. New estimation problems. Full multilevel models need MCMC to estimate them.

  3. More difficult interpretation. Multilevel models make predictions at different levels of the data. Frequently, only one or two of these levels are important for our question. Thus, model comparison with WAIC (or DIC) is more subtle. The basic logic does not change. But we must make more decisions about which parameters in the model are important for us.

3.3 Names for these models

Multilevel models have many different names. Some statisticians use the same name for different special types of model. Other statisticians use the names as if they are all the same.

  • The most common other names for multilevel models are hierarchical modelsᴳ and mixed effects modelsᴳ.

  • The parameters in multilevel models are frequently called random effectsᴳ. But this name has different meanings for different analysts and in different contexts.

  • Even the word "level" has different meanings for different people.

The only solution is to ask for a mathematical or algorithmic definition of the model. If you do not have it, the model is ambiguous.

Main point: The reed frog data have 48 tanks of tadpoles. Each tank is a cluster. A model with a separate intercept for each tank has amnesia: it learns nothing about one tank from the other tanks.

In this paper, we use only the number that survived, surv, out of the initial number, density. The other variables are experimental treatments. The practice problems at the end of Chapter 13 in the textbook use them.

4.2 Tanks are clusters

These data have much variation. Some of the variation comes from the experimental treatments. But much of it comes from other sources. Think of each row as a "tank": an experimental environment that contains tadpoles. Each tank has many special conditions that we did not measure. These conditions cause variation in survival across the tanks, even when all the predictor variables have the same values.

The tanks are an example of a cluster variable. We make many observations (here, the tadpoles) in each cluster. Thus, we have repeated measures and heterogeneity across the clusters.

  • If we ignore the clusters and give the same intercept to all of them, then we possibly ignore important variation in the baseline survival. This variation can hide associations with other variables.

  • If we estimate a separate intercept for each cluster, with a dummy variable for each tank, then we have amnesia. The tanks are different, but each tank helps us to estimate the survival in the other tanks. Thus, it is not sensible to forget all that we learned when we go from one tank to the next.

We want a multilevel model. This model estimates an intercept for each tank and also the variation among the tanks, at the same time. This is a varying interceptsᴳ model. Varying intercepts are the simplest type of varying effectsᴳ. Each cluster in the data has its own intercept parameter. This is the same as the categorical variables in the previous papers. But now the model also learns the prior that is common to all the intercepts. This is adaptive learning, and it is the opposite of amnesia. What we learn about each cluster gives information about all the other clusters. Thus, we learn the prior at the same time as we learn the intercepts.

4.3 The model with amnesia

First, make a model that predicts tadpole survival in each tank. It uses the regularizing priors of the earlier papers:

Si∼Binomial(Ni,pi)logit(pi)=αTANK[i][a separate log-odds for each tank]αj∼Normal(0,1.5)for j=1,…,48\begin{aligned} S_i &\sim \text{Binomial}(N_i, p_i) \\ \text{logit}(p_i) &= \alpha_{\text{TANK}[i]} && \text{[a separate log-odds for each tank]} \\ \alpha_j &\sim \text{Normal}(0, 1.5) && \text{for } j = 1, \dots, 48 \end{aligned}

Fit the model with PyMC. Each row of the data is one tank, so the tank index is the row number:

S = d["surv"].values
N = d["density"].values
tank = np.arange(len(d))              # one index for each tank: 0 to 47
coords = {"tank": np.arange(1, len(d) + 1)}

with pm.Model(coords=coords) as m13_1:
    a = pm.Normal("a", 0, 1.5, dims="tank")
    p = pm.math.invlogit(a[tank])
    pm.Binomial("S", n=N, p=p, observed=S)
    idata_13_1 = pm.sample(1000, chains=4, random_seed=1,
                           idata_kwargs={"log_likelihood": True})

The posterior has 48 different intercepts, one for each tank. To see them, use az.summary(idata_13_1). To get the expected survival probability of a tank, take its value of a and use the logistic transform (expit). There is nothing new here.

5. The multilevel model

Main point: In a multilevel model, the prior for the tank intercepts has its own parameters, and the model learns them from the data. This prior is an adaptive prior. It shrinks the intercepts towards their mean, so the model has fewer effective parameters.

5.1 The adaptive prior

Now make the multilevel model. This model pools information across the tanks adaptively. To get adaptive pooling, make the prior for the a parameters a function of some new parameters. The model is:

Si∼Binomial(Ni,pi)logit(pi)=αTANK[i]αj∼Normal(αˉ,σ)[adaptive prior]αˉ∼Normal(0,1.5)[prior for the average tank]σ∼Exponential(1)[prior for the standard deviation of tanks]\begin{aligned} S_i &\sim \text{Binomial}(N_i, p_i) \\ \text{logit}(p_i) &= \alpha_{\text{TANK}[i]} \\ \alpha_j &\sim \text{Normal}(\bar{\alpha}, \sigma) && \text{[adaptive prior]} \\ \bar{\alpha} &\sim \text{Normal}(0, 1.5) && \text{[prior for the average tank]} \\ \sigma &\sim \text{Exponential}(1) && \text{[prior for the standard deviation of tanks]} \end{aligned}

The changes from the model in Section 4.3 are in the last three lines. The prior for the tank intercepts is now a function of two parameters, ᾱ and σ. Say ᾱ as "alpha bar". The bar means "average".

These two parameters in the prior are the reason for the word "multi" in "multilevel". The Gaussian distribution with mean ᾱ and standard deviation σ is the prior for the intercept of each tank. But this prior has its own priors for ᾱ and σ. Thus, the model has two levels. Each level is similar to a simpler model:

Level 1Level 2
OutcomeSthe vector of intercepts α
Parametersthe vector αᾱ and σ
Priorαj ~ Normal(ᾱ, σ)ᾱ ~ Normal(0, 1.5) and σ ~ Exponential(1)

The parameters ᾱ and σ are hyperparametersᴳ. They are parameters for parameters. Their priors are hyperpriorsᴳ. You can put as many "hyper" levels in a model as you like. For example, different populations of tanks can be in different regions of habitat. But in practice there are limits, because of computation and because we must understand the model.

5.2 Why Gaussian tanks?

In this model, the population of tanks is Gaussian. Why?

  • Convention. This is the least satisfactory answer. The Gaussian assumption is very common.

  • Pragmatism. The Gaussian assumption is easy to use. It also extends easily to more than one dimension. This is important for varying slopes, in the next class session.

  • Entropy. This is the best answer. If we know only the mean and the variance of a distribution, then the Gaussian distribution is the most conservative assumption (Chapter 10 in the textbook).

A Gaussian prior does not force the posterior distribution of the α parameters to be symmetric or to have a Gaussian shape. The only information in a Gaussian prior (or likelihood) is a finite variance. The distribution looks symmetric because we do not say how it is skewed. When we do not say this, the maximum entropy shape is symmetric.

There is no rule that varying effects must have a Gaussian distribution. If you have a good reason to use a different distribution, use it. The practice problems at the end of Chapter 13 in the textbook give an example.

5.3 Fit the multilevel model

The posterior calculation estimates the two levels at the same time. This is the same as the coffee robot in Section 2.2: it learned about each café and about the variation among the cafés.

with pm.Model(coords=coords) as m13_2:
    a_bar = pm.Normal("a_bar", 0, 1.5)
    sigma = pm.Exponential("sigma", 1)
    a = pm.Normal("a", a_bar, sigma, dims="tank")      # adaptive prior
    p = pm.math.invlogit(a[tank])
    pm.Binomial("S", n=N, p=p, observed=S)
    idata_13_2 = pm.sample(1000, chains=4, random_seed=1,
                           idata_kwargs={"log_likelihood": True})

5.4 Compare the models with WAIC

Compare the effective number of parametersᴳ of the two models. ArviZ 1.x does not have a WAIC function (it was deprecated), so the code below calculates WAIC directly from the pointwise log-likelihoods. The result is on the deviance scale, the same scale as in the textbook.

def waic(idata):
    """WAIC on the deviance scale, and the effective number of parameters."""
    ll = idata.log_likelihood["S"].values.reshape(-1, len(S))   # samples x observations
    lppd = np.sum(np.log(np.mean(np.exp(ll), axis=0)))
    p_waic = np.sum(np.var(ll, axis=0))
    return -2 * (lppd - p_waic), p_waic

pd.DataFrame([waic(idata_13_2), waic(idata_13_1)], index=["m13_2", "m13_1"],
             columns=["WAIC", "pWAIC"]).round(1)

The textbook gives WAIC = 200.0 and pWAIC = 20.9 for m13.2, and WAIC = 215.9 and pWAIC = 26.2 for m13.1.

There are two important facts here:

  1. The multilevel model has only about 21 effective parameters. It has 50 actual parameters, so there are about 29 fewer effective parameters than actual parameters. The reason is that the prior for each intercept shrinks all the intercepts towards the mean ᾱ. Here, the prior is quite strong: the mean of sigma is approximately 1.6. This is a regularizing priorᴳ, like the priors in the previous papers. But now the model learns the quantity of regularization from the data.

  2. The multilevel model m13_2 has fewer effective parameters than the ordinary model m13_1. This is true although the ordinary model has fewer actual parameters: 48, not 50. The two extra parameters in the multilevel model let it learn a stronger regularizing prior. This is adaptive regularizationᴳ. The result is a less flexible posterior, and thus fewer effective parameters.

6. Shrinkage and the population of tanks

Main point: The multilevel estimates move towards the average of all the tanks. Small tanks, and tanks far from the average, move the most. This is shrinkage. It comes from pooling information across the tanks.

6.2 Three effects of shrinkage

The plot shows three effects:

  1. In each tank, the multilevel estimate is nearer to the dashed line than the raw estimate is. All the black circles move towards the dashed line at the center of the data. The blue points stay on the outside. This effect is shrinkageᴳ. It comes from regularization.

  2. The estimates for the smaller tanks move farther from the blue points. From left to right in the figure, the initial numbers of tadpoles increase from 10 to 25 to 35. In the smallest tanks, the differences between the open circles and the blue points are easy to see. In the largest tanks, the differences are small. Varying intercepts for smaller tanks, with smaller sample sizes, shrink more.

  3. When a blue point is farther from the dashed line, the distance between the blue point and its multilevel estimate is larger. Shrinkage is stronger when the observed proportion of a tank is farther from the average ᾱ.

The three effects have one cause: pooling of information across the clusters (tanks) to make the estimates better. Pooling means that each tank gives information that makes the estimates for all the other tanks better. Each tank can do this because we assumed how the log-odds of each tank relate to all the others. We assumed a distribution: here, the normal distribution. When we have an assumption about the distribution, Bayes' theorem can share information among the clusters in the best possible way (but only in the small world of the model).

6.3 The population of tanks

What does the estimated population distribution of survival look like? To see it, sample from the posterior distribution:

  1. Plot 100 Gaussian distributions, one for each of the first 100 samples of ᾱ and σ from the posterior.

  2. Sample the log-odds of survival for 8000 new tanks. The result is the posterior distribution of the variation in survival in the population of tanks.

Remember that a sample from a posterior distribution is not a simulation of empirical sampling. It is only a convenient method to describe and use the uncertainty in the distribution.

6.4 Varying intercepts as over-dispersion

In the previous class session, we saw the beta-binomial and gamma-Poisson models. These models include over-dispersion in count data. Varying intercepts do the same thing: they let count outcomes be over-dispersed. Each observed count has its own intercept, but these intercepts are pooled through a common distribution. Thus, the predictions expect over-dispersion, the same as a beta-binomial or gamma-Poisson model.

A binomial or Poisson model with a varying intercept for each observed outcome is often easier to estimate and easier to extend than a beta-binomial or gamma-Poisson model.

6.5 Priors for variance components

The models in this paper use weakly regularizing exponential priors for the variance componentsᴳ. These are the σ parameters, which estimate the variation across the clusters in the data. Exponential priors work very well in routine multilevel models. They give only an approximate average standard deviation, and they regularize towards zero.

But there are two common situations in which exponential priors can cause problems:

  1. The data do not have much information about the variance. For example, if you have only 5 clusters, then this is similar to an estimate of a variance from 5 data points. Then you possibly need a much more informative prior.

  2. In non-linear models with logit and log links, floor and ceiling effects can make extreme values of the variance as plausible as more realistic values. Then the trace plot for the variance parameters can move about over very large values. This can occur because the exponential prior has a long tail. Usually, such large values are not possible before you see the data. Frequently, the chains still sample correctly, but they can be very inefficient: they can have small effective sample sizes and many divergent transitions.

To make such a model better, use a half-Normalᴳ prior, or a different prior with a thin tail, for the variance components. A half-Normal distribution is a Normal distribution with all of its probability above zero. The part below zero is removed. Compare the two priors:

s = np.linspace(0, 5, 300)
fig, ax = plt.subplots(figsize=(5, 3.2))

ax.plot(s, stats.halfnorm.pdf(s, scale=1), color=BLUE, lw=2, ls="--", label="Half-Normal(0, 1)")
ax.set_xlabel("sigma")
ax.set_ylabel("density")

plt.show()

Figure 3. Two priors for a standard deviation σ. The exponential prior has a longer tail. With Exponential(1), the probability that σ is more than 3 is approximately 5%. With Half-Normal(0, 1), it is approximately 0.3%.

The multilevel model with a half-Normal prior is:

Si∼Binomial(Ni,pi)logit(pi)=αTANK[i]αj∼Normal(αˉ,σ)αˉ∼Normal(0,1.5)σ∼Half-Normal(0,1)\begin{aligned} S_i &\sim \text{Binomial}(N_i, p_i) \\ \text{logit}(p_i) &= \alpha_{\text{TANK}[i]} \\ \alpha_j &\sim \text{Normal}(\bar{\alpha}, \sigma) \\ \bar{\alpha} &\sim \text{Normal}(0, 1.5) \\ \sigma &\sim \text{Half-Normal}(0, 1) \end{aligned}

In PyMC, use pm.HalfNormal. It is already zero below zero, so you do not set a lower bound.

For the tadpole data, the two priors give almost the same posterior. The data have much information about σ, so the tail of the prior is not important here.

7. Complete, no and partial pooling

Main point: Complete pooling underfits. No pooling overfits. Partial pooling, with varying intercepts, is between the two. Thus, on average, it gives better estimates for each cluster.

7.1 Varying effects and the trade-off

Varying intercepts are regularized estimates. But they are adaptively regularized: the model estimates how different the clusters are while it estimates the features of each cluster. This is not easy to understand. This section relates the multilevel estimates to the basic problem of underfitting and overfitting.

Varying effect estimates are more accurate estimates of the intercepts of the individual clusters (tanks) than the raw empirical estimates. On average, they give a better estimate of the mean of each tank. The reason is that they make a better trade-off between underfittingᴳ and overfittingᴳ.

7.2 Three approaches

Think of the reed frog example again. But now we have natural ponds, not experimental tanks. Thus, we want to predict survival in the same ponds (clusters) in the future. There are three approaches to this prediction:

  1. Complete poolingᴳ. We assume that the population of ponds does not change. This is the same as an estimate of one common intercept for all the ponds.

  2. No poolingᴳ. We assume that each pond gives no information about the other ponds. This is the model with amnesia.

  3. Partial poolingᴳ. We use an adaptive regularizing prior, as in Sections 5 and 6.

Complete pooling underfits. Suppose that you ignore the varying intercepts. You use the overall mean across all the ponds, ᾱ, to predict each pond. Much data goes into the estimate of ᾱ, so this estimate can be quite precise. But the estimate of ᾱ probably does not agree exactly with the mean of a particular pond. Thus, the total sample mean underfits the data. This model pools the data from all the ponds to make one estimate, and it uses this estimate for each pond. It assumes that the variation among the ponds is zero: all the ponds are the same.

No pooling overfits. Suppose that you use the survival proportion of each pond to predict that pond. This means a separate intercept for each pond. The blue points in Figure 1 are this type of estimate. In each pond, only a small quantity of data goes into each estimate. Thus, these estimates are not precise. This is especially true for the smaller ponds, which have less data. Thus, the errors of these estimates are large, and the estimates overfit the data. The standard error of each intercept can be very large, and in extreme cases it can be infinite. No information goes from one pond to another. This is the same as an assumption that the variation among the ponds is infinite. Thus, nothing that you learn from one pond helps you to predict another pond.

Partial pooling is between the two. When you estimate varying intercepts, you pool the information partially. The estimate for each cluster underfits less than the grand mean, and it overfits less than the no-pooling estimate. Thus, the partial pooling estimates are usually better estimates of the true mean of each cluster (pond). This is especially true when the ponds have few tadpoles, because then the no-pooling estimates overfit very much. When each pond has much data, the varying effect estimates and the no-pooling estimates are more similar.

7.3 Show it with a simulation

To show this, simulate some tadpole data. Then we know the true survival probability of each pond. We can compare the no-pooling estimates with the partial pooling estimates. We calculate how near each estimate is to the true value. Sections 8 and 9 show how to do this simulation.

This skill is very valuable: simulate data, fit the model, and make sure that the model fit is correct. When you use more complex models, you must make sure that your code works and that you understand the model. Simulate data from the model with known parameter values. Then make sure that your estimation method recovers the parameters with acceptable precision. Even a simulation of data from a model structure helps you to understand the model very much.

8. Simulate tadpole ponds

Main point: Simulate ponds from the multilevel model with known values of ᾱ and σ. Then you know the true survival probability of each pond, and you can measure the error of each estimate.

8.1 The model

Use the same basic multilevel binomial model as before, but with "ponds" in place of "tanks":

Si∼Binomial(Ni,pi)logit(pi)=αPOND[i]αj∼Normal(αˉ,σ)αˉ∼Normal(0,1.5)σ∼Exponential(1)\begin{aligned} S_i &\sim \text{Binomial}(N_i, p_i) \\ \text{logit}(p_i) &= \alpha_{\text{POND}[i]} \\ \alpha_j &\sim \text{Normal}(\bar{\alpha}, \sigma) \\ \bar{\alpha} &\sim \text{Normal}(0, 1.5) \\ \sigma &\sim \text{Exponential}(1) \end{aligned}

To simulate data from this process, give values to:

  • ᾱ, the average log-odds of survival in the full population of ponds

  • σ, the standard deviation of the distribution of log-odds of survival among the ponds

  • α, a vector of intercepts, one for each pond

We also need a sample size Ni for each pond. Then we can simulate the counts of surviving tadpoles directly from the binomial process at the top level, with rng.binomial. Do each step one at a time.

The priors are part of the model when we estimate, but not when we simulate. Why? Because priors are epistemology, not ontology. They show the initial information of our robot. They do not show how nature selects parameter values.

8.2 Give values to the parameters

The values below are similar to the real tadpole data. Thus, the plot in Section 9 shows the better accuracy of the varying effects estimates clearly. You can come back to this step later and change the values.

8.3 Simulate the survivors

Now simulate the binomial survival process. Each pond i has Ni possible survivors. Nature tosses a coin for each tadpole, with probability of survival pi. The model definition gives this probability:

pi=exp⁡(αi)1+exp⁡(αi)p_i = \frac{\exp(\alpha_i)}{1 + \exp(\alpha_i)}

The model uses a logit link, so the logistic function (expit) gives the probability. Put the logistic function into the random binomial function, and simulate a count of survivors for each pond:

dsim["Si"] = rng.binomial(dsim["Ni"], expit(dsim["true_a"]))

When you give NumPy a list of values, it gives a new list of the same length. Here, each pair of αi (true_a) and Ni gives a random count of survivors, with the correct probability of survival and the correct maximum count. The counts go into a new column in dsim.

8.4 Data types

There are two basic types of numbers in NumPy: integers and floating-point (real) values. A number like 3 can be either type. Inside the computer, the two types are different:

print(np.arange(1, 4).dtype)
print(np.array([1.0, 2.0, 3.0]).dtype)
int64
float64

Usually, you do not have to control these types. But in a binomial model, the size variable (the number of trials) must be an integer. If it is a float, then the model can give errors or warnings that are difficult to understand. Thus, make sure that the counts are integers before you give them to a model. You can change the type with .astype(int). In Section 8.2, np.repeat of a list of integers gives integers, so Ni is correct.

9. Compare no-pooling and partial-pooling estimates

Main point: On average, the partial pooling estimates are nearer to the true values than the no-pooling estimates. The improvement is largest in the smallest ponds. But partial pooling is not better in every pond.

9.1 Calculate the no-pooling estimates

Now analyze the simulated data. The easiest task is to calculate the no-pooling estimates. Calculate them directly from the data: the proportion of survivors in each pond. Keep these estimates on the probability scale, not the log-odds scale, because we compare the quality of the estimates on the probability scale later.

dsim["p_nopool"] = dsim["Si"] / dsim["Ni"]

Now dsim has another column with the observed proportions of survivors in each pond. These are the same no-pooling estimates that you get from a model with a dummy variable for each pond and flat priors, which give no regularization.

9.2 Calculate the partial-pooling estimates

Now fit the multilevel model to the simulated data. Always use more than one chain, so that you can examine the convergence to the correct posterior distribution.

The code puts the survivor counts in pm.Data. Then Section 9.5 can give new data to the same model.

9.4 Interpret the errors

Figure 4 and the table show three facts:

  1. Both types of estimate are much more accurate for the larger ponds, on the right. The reason is that more data gives better estimates, if there is no confounding. (If there is confounding, more data can make the estimates worse. But there is no confounding in this simulation.) In the small ponds, the sample size is small, and neither no pooling nor partial pooling can do magic. Thus, the predictions are worse on the left of the plot.

  2. The blue line is above or very near the dashed black line in each group. Thus, the no-pooling estimates have a higher average error in each group of ponds, except for the large ponds in this simulation. (In the textbook's simulation, the exception is the medium ponds.) Partial pooling is not always better. It is better on average, in the long run. Both types of estimate become worse when the sample size decreases, but the varying effect estimates have the advantage, on average.

  3. The distance between the blue line and the dashed black line increases when the ponds become smaller. Both types of estimate become worse with a smaller sample size, but the partial pooling estimates become worse less quickly.

What does this mean? In Figure 1, the smaller tanks had more shrinkage towards the mean. Here, the ponds with the smallest sample size have the largest improvement over the no-pooling estimates. This is not a coincidence:

  • Shrinkage towards the mean comes from a trade-off between two risks. At one end, the grand mean underfits. At the other end, the mean of each individual pond overfits.

  • The smaller tanks and ponds have less information. Thus, the pooled information from the other ponds has a larger influence on their varying estimates. Small ponds easily overfit, so they get a larger dose of the underfit grand mean.

  • The larger ponds shrink much less, because they have more information and they overfit less. Thus, they need less correction.

  • When the individual ponds are very large, pooling does almost nothing to make the estimates better, because the estimates do not have far to move. But pooling also does no harm in this case. And the information pooled from the large ponds can help the predictions in the smaller ponds very much.

The partially pooled estimates are better on average. They adjust the estimates of the individual clusters (ponds) to get a good trade-off between underfitting and overfitting. This is a type of regularization. But now the model learns the quantity of regularization from the data.

In some cases, the no-pooling estimates are better. These cases often come from ponds with extreme probabilities of survival. The partial pooling estimates shrink these extreme ponds towards the mean, because few ponds are so extreme. But sometimes outliers really are outliers.

9.5 Repeat the simulation

Figure 4 shows a typical pattern, but it comes from only one random simulation. Do the simulation again with new data. The model m13_3 keeps the survivor counts in pm.Data. Thus, pm.set_data gives new counts to the same model, and you do not have to build the model again.

def repeat_simulation(seed):
    rng = np.random.default_rng(seed)
    dsim = pd.DataFrame({"pond": np.arange(1, nponds + 1), "Ni": Ni,
                         "true_a": rng.normal(a_bar_true, sigma_true, nponds)})
    dsim["Si"] = rng.binomial(dsim["Ni"], expit(dsim["true_a"]))
    dsim["p_nopool"] = dsim["Si"] / dsim["Ni"]
    with m13_3:                                        # the same model, new data
        pm.set_data({"Si_data": dsim["Si"].values})
        idata = pm.sample(1000, chains=4, random_seed=seed, progressbar=False)
    post = idata.posterior.to_dataset().stack(s=("chain", "draw"))
    dsim["p_partpool"] = expit(post["a_pond"]).mean("s").values
    dsim["p_true"] = expit(dsim["true_a"])
    nopool_error = np.abs(dsim["p_nopool"] - dsim["p_true"])
    partpool_error = np.abs(dsim["p_partpool"] - dsim["p_true"])
    return dsim, nopool_error, partpool_error

dsim2, e_no, e_part = repeat_simulation(seed=7)
plot_errors(dsim2, e_no, e_part)

10. Glossary

The terms are in alphabetical order. The links in the text go to these entries.

Adaptive regularization

Regularization in which the model learns the strength of the prior from the data. A multilevel model does this when it estimates σ.

Cluster

A group of observations that come from the same unit, for example the same individual, location, time, tank or pond.

Complete pooling

An approach that uses one common estimate for all the clusters. It assumes that the variation among the clusters is zero. It underfits.

Dummy variable

A variable that is 1 for one category and 0 for all the other categories. A model with a dummy variable or an index variable for each cluster gives each cluster a separate parameter.

Effective number of parameters

A measure of the flexibility of a model, from WAIC (pWAIC) or PSIS. It is not always the same as the number of parameters.

Half-Normal distribution

A Normal distribution with all of its probability above zero. It is a prior with a thin tail for a standard deviation.

Hierarchical model

Another name for a multilevel model.

Hyperparameter

A parameter of the prior for other parameters. In the tadpole model, ᾱ and σ are hyperparameters.

Hyperprior

The prior for a hyperparameter.

Mixed effects model

Another name for a multilevel model.

Multilevel model

A model that estimates a parameter for each cluster and also the distribution of these parameters across the clusters, at the same time. Thus, it pools information across the clusters.

No pooling

An approach that uses a separate estimate for each cluster, with no information from the other clusters. It assumes that the variation among the clusters is infinite. It overfits.

Overfitting

When a model learns too much from the sample, so that it predicts new data badly.

Partial pooling

An approach that uses an adaptive regularizing prior, so that each cluster gets information from the other clusters. A multilevel model does partial pooling.

Pooling

The use of information from all the clusters to make the estimate for each cluster better.

Random effects

A common name for the varying parameters in a multilevel model. It has different meanings for different analysts.

Regularizing prior

A prior that makes the model learn less from the sample, so that it overfits less.

Shrinkage

The movement of the cluster estimates towards the average of all the clusters in a multilevel model. Clusters with less data, and clusters far from the average, shrink more.

Underfitting

When a model learns too little from the sample, so that it misses important features of the data.

Variance component

A parameter that estimates the variation across the clusters, for example σ in the tadpole model.

Varying effects

Parameters that have a different value for each cluster, with a common distribution that the model learns from the data.

Varying intercepts

Varying effects that are intercepts: each cluster has its own intercept, from a common distribution.
