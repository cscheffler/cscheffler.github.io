2. Why posterior predictions

Main point: Posterior predictions help us to check a model, to understand it, to estimate causal effects and to calculate information criteria. In multilevel models, the predictions do not match the raw data exactly, and "prediction" needs more decisions.

2.1 Three uses of posterior predictions

Chapter 3 in the textbook explains why model checks are important. Software does not always work correctly. A robust way to find mistakes is to compare the sample to the posterior predictionsᴳ of the fitted model.

The same procedure, to make the predictions that a fitted model implies, also helps us to understand what the model means. Each model is a mix of sense and nonsense. When we understand a model, we can find its sense and control its nonsense. But when models become more complex, it is very difficult or impossible to understand them only from tables of posterior means and intervals. The implied posterior predictions help much more.

Posterior predictions have three uses:

  1. Model checks. Compare the predictions to the sample to find mistakes.

  2. Causal effects. When you think that the posterior is correct, use predictions to estimate the causal effects. What is the estimated effect of an intervention on one or more variables? To answer this question, we need counterfactualᴳ posterior predictions. Chapter 5 in the textbook gives an example.

  3. Information criteria. We need implied predictions to calculate information criteria, for example AIC and WAIC. These criteria give simple estimates of the out-of-sample accuracy of a model (the KL divergenceᴳ). In practice, they give an approximate measure of the flexibility of a model, and thus of its risk of overfitting. Chapter 7 in the textbook explains this.

2.2 Two new points for multilevel models

All of this advice also applies to multilevel models. We still need model checks, counterfactual predictions and information criteria. But varying effects add two new points:

  1. We must not expect the model to retrodictᴳ the sample exactly. The goal of adaptive regularization is to accept a worse fit in the sample, to get better inference and possibly a better fit out of the sample. This is what shrinkage does. (We must never really try to retrodict the sample exactly.) But now, even a very good model will be different from the raw data in a systematic way.

  2. "Prediction" in a multilevel model needs more decisions. Predictions for the same clusters that we used to fit the model are one task. Predictions for new clusters, which are not in the sample, are a different task.

Section 3 shows the first task, and Section 4 shows the second task. The two sections use the chimpanzee model from the previous paper.

3. Predictions for the same clusters

Main point: For the clusters in the sample, the varying intercepts are ordinary parameters. Use the correct intercept for each case. You can let PyMC calculate the predictions, or you can calculate them yourself from the posterior samples and the model definition.

3.1 Fit the chimpanzee model again

When you use the same clusters that you used to fit the model, the varying intercepts are only parameters. The only trick is to use the correct intercept for each case in the data. If PyMC calculates the predictions for you, it does this automatically. If you calculate them yourself, use the model definition.

For example, the chimpanzee data have 7 different actors. These are the clusters. The varying intercepts model m13_4 estimated an intercept for each actor. It also estimated two parameters for the mean and the standard deviation of the population of actors.

Fit the model again. This paper uses the non-centered form from the previous paper, because it samples better. The posterior is the same as for m13_4. The code adds three changes:

  • pm.Data holds the index variables, so that we can give new values to the model later.

  • pm.Deterministic keeps p, the probability of a left pull, in the posterior.

  • shape=actor_d.shape lets the number of cases change when the data change.

d = pd.read_csv(DATA + "chimpanzees.csv", sep=";")
actor = d["actor"].values - 1                                   # 0 to 6
block_id = d["block"].values - 1                                # 0 to 5
treatment = (d["prosoc_left"] + 2 * d["condition"]).values      # 0 to 3
L = d["pulled_left"].values
coords = {"actor": np.arange(1, 8), "block": np.arange(1, 7), "treatment": np.arange(1, 5)}

with pm.Model(coords=coords) as m13_4nc:
    actor_d = pm.Data("actor_d", actor)
    block_d = pm.Data("block_d", block_id)
    treat_d = pm.Data("treat_d", treatment)
    b = pm.Normal("b", 0, 0.5, dims="treatment")
    a_bar = pm.Normal("a_bar", 0, 1.5)
    sigma_a = pm.Exponential("sigma_a", 1)
    sigma_g = pm.Exponential("sigma_g", 1)
    z = pm.Normal("z", 0, 1, dims="actor")             # standardized actor intercepts
    x = pm.Normal("x", 0, 1, dims="block")             # standardized block intercepts
    a = pm.Deterministic("a", a_bar + z * sigma_a, dims="actor")
    g = pm.Deterministic("g", x * sigma_g, dims="block")
    p = pm.Deterministic("p", pm.math.invlogit(a[actor_d] + g[block_d] + b[treat_d]))
    pm.Bernoulli("L", p=p, observed=L, shape=actor_d.shape)
    idata = pm.sample(1000, chains=4, random_seed=13)

print("divergent transitions:", int(idata.sample_stats["diverging"].sum()))
divergent transitions: 0

Before you calculate predictions, remember again: the posterior predictive distribution must not match the raw data exactly, even when the model is correct. Why? The purpose of partial pooling is to shrink the estimates towards the grand mean. Thus, when you use pooling, the estimates do not necessarily agree with the raw data.

3.2 Let PyMC calculate the predictions

The code below calculates the posterior predictions (retrodictions) for actor 2, in block 1, for each of the four treatments. It is like the code in the paper about binomial regression:

  1. Give new values to the index variables with pm.set_data.

  2. Use pm.sample_posterior_predictive to calculate p for each posterior sample. This does the same work as link in the textbook.

chimp = 1                                   # actor 2 (index 1)
with m13_4nc:
    pm.set_data({"actor_d": np.repeat(chimp, 4),
                 "block_d": np.repeat(0, 4),
                 "treat_d": np.arange(4)})
    pred = pm.sample_posterior_predictive(idata, var_names=["p"],
                                          random_seed=1, progressbar=False)

p = pred.posterior_predictive["p"].stack(s=("chain", "draw")).values   # 4 x samples
p_mu = p.mean(axis=1)
p_ci = np.percentile(p, [5.5, 94.5], axis=1)
print(p_mu.round(3))
[0.979 0.988 0.971 0.986]

3.3 Calculate the predictions yourself

To do the same calculation without PyMC, you only have to remember the model. The only difficulty is that the varying intercepts are a matrix of samples. Get the posterior samples as arrays, with the samples on the first axis:

post = {k: v.values for k, v in
        idata.posterior.to_dataset()[["b", "a", "g", "a_bar", "sigma_a", "sigma_g"]]
        .stack(s=("chain", "draw")).transpose("s", ...).items()}
for k, v in post.items():
    print(f"{k:8s}", v.shape)
b        (4000, 4)
a        (4000, 7)
g        (4000, 6)
a_bar    (4000,)
sigma_a  (4000,)
sigma_g  (4000,)

The a matrix has the samples on the rows and the actors on the columns. Thus, post["a"][:, 4] means "all the samples for actor 5". The left plot in Figure 1 shows its density.

To make the posterior predictions, write your own link function:

def p_link(treatment, actor=0, block_id=0):
    logodds = post["a"][:, actor] + post["g"][:, block_id] + post["b"][:, treatment]
    return expit(logodds)

p_raw = np.column_stack([p_link(i, actor=1, block_id=0) for i in range(4)])  # samples x 4
p_mu = p_raw.mean(axis=0)
p_ci = np.percentile(p_raw, [5.5, 94.5], axis=0)
print(p_mu.round(3))
[0.979 0.988 0.971 0.986]

The linear model is the same as in the model definition. The only change is [:, ...]: it takes all the samples for one actor, one block and one treatment. The result is the same as in Section 3.2.

Plot the density of a[5] and the predictions for actor 2:

labels = ["R/N", "L/N", "R/P", "L/P"]

4. Predictions for new clusters

Main point: For new clusters, use the population parameters a_bar and sigma_a to simulate new actors. Predictions for an average actor show the effect of treatment. Predictions marginal of actor show the variation among actors. A plot of many simulated actors shows both.

4.1 Generalize from the sample

To make predictions for new clusters is to generalize from the sample. In general, there is no single correct procedure to generalize predictions outside a sample. The correct procedure depends on the causal model, the statistical model and your goals. But if you have a generative model, you can often find the procedure when you think about it. The key idea is this: use the posterior to set the parameters of a simulation that represents the generalization that you want.

For example, suppose that you want to predict how chimpanzees in a different population will respond to the lever experiment. The 7 chimpanzees in the sample let us estimate 7 different intercepts. But these individual actor intercepts are not useful here, because none of these 7 individuals is in the new population.

To understand the task, think that you leave out one cluster when you fit the model. For example, leave out actor 7. How can you then measure the accuracy of the model when it predicts the behaviour of actor 7? You cannot use the a estimates, because they apply to other individuals. But you can use a_bar and sigma_a. These parameters describe a statistical population of actors, and you can simulate new actors from it.

4.2 An average actor

First, make posterior predictions for a new, average actor. "Average" means a chimpanzee with an intercept exactly at a_bar (ᾱ), the population mean. There is uncertainty about the population mean, so there is still uncertainty about the intercept of this average actor. But this uncertainty is much smaller than it must be, if we want to show honestly what to expect from a new individual.

Write a new link function:

def p_link_abar(treatment):
    logodds = post["a_bar"] + post["b"][:, treatment]
    return expit(logodds)

p_raw_abar = np.column_stack([p_link_abar(i) for i in range(4)])

The function ignores block. The reason is that we predict for new blocks, so we assume that the average block effect is approximately zero (as it was in the sample). The left plot in Figure 2 shows the result. The shaded region is the 89% compatibility interval for an actor with an average intercept. This plot shows the effect of prosoc_left clearly, and also the uncertainty about where the average is. But it does not show the variation among the actors.

4.3 Marginal of actor

To show the variation among the actors, use sigma_a in the calculation:

  1. Sample some random chimpanzees from a normal distribution with mean a_bar and standard deviation sigma_a.

  2. Write a link function that uses these simulated chimpanzees, not the chimpanzees in the posterior.

Sample the chimpanzees outside the link function. The reason is that each treatment must use the same simulated chimpanzee.

a_sim = rng.normal(post["a_bar"], post["sigma_a"])     # one new actor for each sample

def p_link_asim(treatment):
    logodds = a_sim + post["b"][:, treatment]
    return expit(logodds)

p_raw_asim = np.column_stack([p_link_asim(i) for i in range(4)])

The middle plot in Figure 2 shows the result. These posterior predictions are marginalᴳ of actor. This means that they average over the uncertainty among the actors. The predictions in the left plot set the actor to the average, and they ignore the variation among the actors.

4.4 Simulated actors

We can make a better plot that shows the treatment effect and the variation among the actors together. Do not summarize with intervals. Simulate a series of new actors in each of the four treatments. Draw one line for each actor across the four treatments. Then you can see the zig-zag effect of prosoc_left and also the variation among the individuals.

You do not need new calculations. Each row in p_raw_asim is a single trend: one simulated chimpanzee. Thus, plot the rows, and do not calculate the mean and the interval. The code below makes all three plots of Figure 2:

def panel(ax, title):
    ax.set_ylim(0, 1)
    ax.set_xticks(range(4), labels)
    ax.set_xlabel("treatment")
    ax.set_ylabel("proportion pulled left")
    ax.set_title(title)

fig, axes = plt.subplots(1, 3, figsize=(12, 3.6))
for ax, pr, title in [(axes[0], p_raw_abar, "average actor"),
                      (axes[1], p_raw_asim, "marginal of actor")]:
    lo, hi = np.percentile(pr, [5.5, 94.5], axis=0)
    ax.fill_between(range(4), lo, hi, color="#000000", alpha=0.15, lw=0)
    ax.plot(range(4), pr.mean(axis=0), color=DARK, lw=2)
    panel(ax, title)

# right: 100 simulated actors, one line each
for i in range(100):
    axes[2].plot(range(4), p_raw_asim[i], color="#000000", alpha=0.25, lw=1.5)
panel(axes[2], "simulated actors")
plt.tight_layout()
plt.show()

Figure 2. Posterior predictive distributions for the chimpanzee varying intercepts model m13_4. The solid lines are posterior means, and the shaded regions are 89% intervals. Left: when the varying intercept a is set to the mean a_bar, we get predictions for an average actor. These predictions ignore the uncertainty from the variation among actors. Middle: when we simulate varying intercepts with the posterior standard deviation among actors, sigma_a, the predictions include the variation among actors. Right: 100 simulated actors, each with its own intercept sampled from the posterior. Each simulation keeps the same parameter values across all four treatments.

In the right plot, each line is a simulated actor, across the four treatments on the horizontal axis. In this plot, it is much easier to see the zig-zag effect of treatment and also the variation among the actors that comes from the posterior distribution of sigma_a.

The plot also shows an interaction between treatment and the variation among the actors. This is a binomial model, so in principle all the parameters interact, because of ceiling and floor effectsᴳ:

  • For actors with very large intercepts, near the top of the plot, treatment has very little effect. These actors have strong preferences for one hand.

  • Actors with intercepts nearer the mean respond more to treatment.

4.5 Which predictions to use?

Students usually ask: "Which one must I use?" The answer is: "It depends." Each type is useful for a different question:

  • The predictions for an average actor help you to see the effect of the treatment.

  • The predictions that are marginal of actor show how different the chimpanzees are, according to the model.

When you try to understand a model, calculate both types for yourself. Which type you put in a report depends on the context. For these data, the plot of simulated actors is better, because it shows the treatment effect and the variation among actors together.

5. Post-stratification

Main point: Post-stratification makes predictions for a population from a sample that does not represent it. Estimate the outcome for each demographic category, then weight the estimates by the size of each category in the population. It does not work when the outcome causes the selection.

5.1 The idea

A common problem is this: we have a sample that does not represent the population, and we want predictions that do represent the same population. For example, we ask possible voters about how they will vote. Such samples are almost always biased, because different groups respond to surveys at different rates. Thus, if we use only the average of the survey, our prediction for the election will be wrong. How can we do better?

One method is post-stratificationᴳ:

  1. Fit a model in which each demographic category of the population has its own predicted voting intention. A category is a specific combination of variables, for example age, income and education.

  2. Weight these predictions again with census information about the full population of voters.

There are usually many demographic categories, and some categories have small samples. Thus, post-stratification is often combined with a multilevel model. This combination is called MRPᴳ ("Mister P"): multilevel regression with post-stratification.

5.2 The calculation

Suppose that you have an estimate pi for each demographic category i. The post-stratified prediction for the full population (not the sample) weights these estimates with the number of individuals N_i in each category in the population:

∑iNipi∑iNi\frac{\sum_i N_i p_i}{\sum_i N_i}

Calculate this for each sample from the posterior distribution. Then you have a posterior distribution of predictions, as usual.

The code below shows the calculation. The posterior samples for three age groups are made-up numbers, not a real model. The survey has many young people, but the population does not:

# posterior samples of the probability of a "yes" vote in 3 age groups (made-up numbers)
p_group = np.column_stack([rng.beta(30, 70, 4000),      # young
                           rng.beta(50, 50, 4000),      # middle
                           rng.beta(70, 30, 4000)])     # old
n_sample = np.array([600, 300, 100])      # people in the survey
N_census = np.array([300, 400, 300])      # people in the population (thousands)

def poststratify(p_group, N):
    return (p_group * N).sum(axis=1) / N.sum()

survey = poststratify(p_group, n_sample)      # weights from the biased sample
mrp = poststratify(p_group, N_census)         # weights from the census
print(survey.mean().round(3), np.percentile(survey, [5.5, 94.5]).round(3))
print(mrp.mean().round(3), np.percentile(mrp, [5.5, 94.5]).round(3))
0.4 [0.351 0.451]
0.5 [0.456 0.545]

With the weights of the survey, the prediction is approximately 0.40. With the weights of the census, it is approximately 0.50. The young people are over-represented in the survey, and they vote "yes" less often. Thus, the survey average is too low. Post-stratification corrects this bias.

5.3 When post-stratification fails

Post-stratification does not always work. It is not justified when the outcome of interest itself causes the selection bias. Let R be the response to the survey, A the age, and V the voting intention:

  • Suppose that age influences the response, and age also influences the voting intention: R ← A → V. Then we can estimate the influence of A on V, and post-stratification on A can correct the bias.

  • Suppose that the voting intention influences the response: V → R. Then there is little hope. For example, suppose that only supporters respond. Then V = 1 for each person who responds.

Selection on the outcomeᴳ variable is one of the worst things that can occur in statistics.

6. Summary of the chapter

Main point: Varying intercepts give better estimates of the baseline differences among clusters, because they model the population of clusters and pool information.

Chapter 13 in the textbook introduced the motivation, the implementation and the interpretation of basic multilevel models:

  • The chapter used varying intercepts. They give better estimates of the baseline differences among the clusters in the data.

  • They give better estimates because they model the population of clusters at the same time as the clusters. They use the inferences about the population to pool information among the parameters.

  • From a different view, varying intercepts are adaptively regularized parameters. Their prior is learned from the data.

This is the foundation for the next class session, which extends these ideas to more types of parameters and models.

7. Glossary

The terms are in alphabetical order. The links in the text go to these entries.

Ceiling and floor effects

In a model with a logit or log link, a probability or rate cannot go above its maximum or below its minimum. Near these limits, a change in a predictor has little effect. Thus, all the parameters interact.

Counterfactual prediction

A prediction for a situation that we did not observe, for example after an intervention on one or more variables. We use it to estimate causal effects.

Generative model

A model that can simulate data. Each Bayesian model is generative: push the posterior samples through the model to get predictions.

KL divergence

A measure of the distance between two probability distributions. Information criteria estimate it for the out-of-sample accuracy of a model.

Marginal

Averaged over the uncertainty in a variable. Predictions marginal of actor average over the variation among actors.

MRP

Multilevel regression with post-stratification. It is also called "Mister P".

Post-stratification

A method that estimates the outcome for each demographic category, and then weights these estimates by the size of each category in the population.

Posterior prediction

A prediction that a fitted model implies, calculated from the posterior samples.

Retrodiction

A posterior prediction for the same data that we used to fit the model.

Selection on the outcome

When the outcome variable itself causes which cases are in the sample. Post-stratification cannot correct it.
