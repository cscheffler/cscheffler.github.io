The Binomial likelihood — Binomial(k | n, p)

The same expression as the Binomial distribution, but read the other way round: the data k and n are now fixed and p varies. Move the sliders and watch which values of p make the observed data more or less plausible.

What this shows

The Binomial likelihood: Binomial(k | n, p) plotted against p, with the data held fixed. It answers “given that I saw k successes in n trials, how plausible is each possible value of p?” — the second half of the globe-tossing story in Chapter 2.

It is the same expression as in the Binomial distribution widget. Fix n and p and vary k, and you get a probability distribution over counts. Fix k and n and vary p, and you get this: a likelihood function. The difference is only which symbol you treat as the variable.

Two consequences worth keeping straight. p is continuous, so this is a smooth curve, where the distribution over whole-number k was a set of separate dots. And this curve is not a probability distribution over p: its area is not 1, so its height alone says nothing about how probable a value of p is. Turning it into one requires a prior and Bayes' theorem.

How to use it

  • k — how many successes were observed. It slides the peak: more successes make larger values of p more plausible. k can never exceed n, so lowering n drags k down with it.
  • n — how many trials were run. More data makes the curve narrower and lower, concentrating plausibility near one region of p.
  • Each slider has a text box beside it for typing an exact value; the arrow keys nudge it, and Shift makes the step ten times bigger.
  • Hover over (or tap) the plot to read off p and the likelihood there.
  • The dashed line marks p̂ = k/n, the value of p that makes the observed data most likely.
  • auto-scale vertical axis — on by default, so the peak always fills the plot. Switch it off to freeze the axis at its current maximum, which is what to do when comparing the heights of two different datasets. A peak above a frozen axis is marked with a caret at the top edge; hovering still reads its true value.

Things to try

  • The globe-tossing data: k = 6, n = 9. The curve peaks at p̂ = 0.667, but note how much height there still is at p = 0.5 — this data is a long way from ruling that out.
  • Now keep the proportion and add data: 6/9, then 12/18, then 24/36. The peak stays at 0.667 while the curve narrows sharply. Same estimate, steadily more confidence — and that narrowing is the whole reason sample size matters.
  • Switch auto-scale off before doing that. Without it the axis quietly rescales each time and hides the fact that the peak is also dropping.
  • Set k = 0, or k = n. The curve stops having an interior peak and piles up against an endpoint: the data are perfectly consistent with p = 0 (or 1), but hardly rule out neighbouring values when n is small.
  • Compare k = 1, n = 2 with k = 50, n = 100. Both have p̂ = 0.5, and the curves could hardly look less alike.

Notes

  • The curve is evaluated once per horizontal pixel, in log space — log n! − log k! − log(n−k)! + k log p + (n−k) log(1−p) — and exponentiated at the end, so the binomial coefficient never overflows.
  • The area under this curve is exactly 1/(n+1), whatever k is, which is another way of seeing that it is not a probability distribution over p. It is reported below the plot so you can watch it shrink as n grows.
  • The vertical scale changes meaning as n changes, so heights are only comparable between datasets when the axis is frozen.
  • The URL updates as you change the inputs, so you can copy it from the address bar and share a particular k and n with someone else. A frozen axis travels with the link too, as &y=, so everyone opening it sees the same scale.
